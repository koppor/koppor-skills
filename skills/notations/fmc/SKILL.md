# FMC block diagrams in PowerPoint

An FMC block diagram shows which active components (agents) of a system exist, which
passive locations (storages, channels) they use, and who may read or change what. The
notation is small, and nearly every element has a look-alike that means something else or
nothing at all. This skill has the notation as a checklist, a stencil deck to copy shapes
from, and a python-pptx library that draws each element correctly.

Scope: block diagrams only. FMC has two more diagram types, Petri nets for dynamic
structures and entity-relationship diagrams for value range structures; their reference
sheets are linked under [Sources](#sources).

## Notation

Everything below is taken from the block diagram reference sheet
([PDF](https://www.fmc-modeling.org/download/notation_reference/Reference_Sheet-Block_Diagram.pdf)).
Open it and compare before calling a diagram done; do not draw from memory.

| Element | Drawn as | Typical mistake |
| --- | --- | --- |
| Agent | Box with corners. Any angular outline is allowed (L or U shapes). Named with a noun. | Rounded corners from a house style: the box then reads as a storage. |
| Human agent | Agent box with a stick figure inside. | Stick figure without the box (that is a UML actor). |
| Storage | Rounded box: stadium, ellipse, or circle. | Rectangle or database cylinder. |
| Channel | Small circle on the line between agents. | Line from agent to agent without a circle. |
| Read access | One line, one filled head **at the agent**. | Head at the storage (that is write access). |
| Write access | One line, one filled head **at the storage**. The agent overwrites the whole content. | Used where the agent only changes parts. |
| Modifying access (read and write) | **Two arcs** bulging apart, one head at the storage, one at the agent. On the sheet the pair runs clockwise: the upper arc points right. | One line with a head at both ends, or a bent polyline. |
| Unidirectional channel | Line, circle, line with **two filled heads**: one where the line enters the circle, one at the receiver. | One head only, or an open head. |
| Bidirectional channel | Plain line through the circle, **no heads**. | Heads at both ends. |
| Request/response channel | Bidirectional channel plus the letter **R** and a small filled triangle beside the circle. The triangle points from the requester to the responder. Horizontal line: `R ▸` above the circle. Vertical line: R and triangle stacked beside the circle. | Triangle pointing to the client, or an arrowhead on the line itself. |
| Request/response, detailed | Two unidirectional channels, named REQ and RES. | Mixed with the R form on the same connection. |
| Shared storage | Two agents, each with modifying access to the same storage. | |
| Structure variance | Storage with a **dashed** outline that contains the agents which come and go. The creating agent has modifying access to this location. | Dashed agent box. |
| Several of a kind | First and last instance, three dots between them. | |

Rules that hold for the whole diagram:

- **Bipartite.** An agent is connected only to storages and channels, a storage or
  channel only to agents. No line runs from agent to agent or from storage to storage.
- **All arrowheads are filled.** An open head does not occur in the notation.
- **Edges are thinner than outlines.** Agents, storages, and channel circles have a heavy
  border, accesses and channel lines a thin one.
- **Nesting.** An agent may contain agents, storages, and channels; a storage may
  contain part storages. An access drawn to the outer storage applies to all parts.
- **The channel name** (protocol, API) stands next to the circle, or inside a circle
  that is large enough.
- **Fill colours carry no meaning in FMC.** The sheet uses grey shades for nesting
  depth. If a deck gives colours a meaning ("grey = external system"), keep it the same
  on every slide and in every other notation of the deck, and say so in a legend.

## Stencil deck

[`assets/fmc-block-diagram-stencil.pptx`](assets/fmc-block-diagram-stencil.pptx) holds

## Library

[`scripts/fmc_pptx.py`](scripts/fmc_pptx.py) needs Python 3.9+ and `python-pptx`.
Coordinates are points from the top left corner of the slide.

```sh
pip install python-pptx
python scripts/fmc_pptx.py stencil fmc-block-diagram-stencil.pptx   # rebuild the stencil
python scripts/fmc_pptx.py check deck.pptx                         # lint, JSON on stdout
```

```powershell
pip install python-pptx
python scripts\fmc_pptx.py stencil fmc-block-diagram-stencil.pptx   # rebuild the stencil
python scripts\fmc_pptx.py check deck.pptx                         # lint, JSON on stdout
```

Drawing into a deck, with `scripts/` on `sys.path`:

```python
import fmc_pptx as fmc

prs = fmc.new_presentation()            # or pptx.Presentation("existing.pptx")
s = fmc.blank_slide(prs)                # or any existing slide

user = fmc.human_agent(s, 60, 185, 70, 90, "Customer")
shop = fmc.agent(s, 390, 90, 330, 340, "Shop server", fill=fmc.SHADE, at="top-left")
web = fmc.agent(s, 410, 130, 110, 200, "Web\napplication")
orders = fmc.agent(s, 590, 130, 110, 60, "Order\nservice")
db = fmc.storage(s, 770, 130, 120, 60, "Orders")

fmc.bidirectional_channel(s, user, web)
fmc.request_response_channel(s, web, orders, name="REST")   # web asks, orders answers
fmc.modifying_access(s, orders, db)
prs.save("shop.pptx")
```

| Function | Draws |
| --- | --- |
| `agent`, `human_agent`, `storage`, `structure_variance` | Nodes. Draw containers first, their content afterwards. |
| `read_access(agent, storage)`, `write_access`, `modifying_access` | Accesses; the argument order is always agent, storage. |
| `bidirectional_channel(a1, a2)`, `unidirectional_channel(sender, receiver)`, `request_response_channel(client, server)` | Line, circle, heads or R marker. `name=` labels the channel, `at=` moves the circle along the line, `label_side=-1` flips the name, `r=` with `name_inside=True` writes it into the circle. |
| `channel(cx, cy)` + `link(agent, channel)` | A channel that more than two agents share. |
| `link(a, b, via=[(x, y)])`, `path(...)` | Lines with bends, free curves. |
| `dots`, `label`, `group` | Repetition dots, free text, PowerPoint group. |

Every edge takes nodes or `(x, y)` points. Between two nodes the line is horizontal or
vertical where their sides overlap, otherwise it runs from centre to centre, and it ends
on the outline, also on the round end of a storage. Passing the wrong kind of node
(`read_access(agent, agent)`) raises a `ValueError` that names the bipartite rule.

House style: set `fmc.INK`, `fmc.PAPER`, `fmc.SHADE`, `fmc.NODE_WIDTH`,
`fmc.EDGE_WIDTH`, `fmc.FONT`, `fmc.FONT_SIZE`, `fmc.HEAD` (`"triangle"` or
`"stealth"`, both filled) before drawing.

## What python-pptx and PowerPoint get wrong on their own

- **Arrowheads have no python-pptx API.** Add `<a:tailEnd type="triangle" w="lg" len="lg"/>`
  to the `a:ln` of the connector. `type="arrow"` is the open head and wrong for FMC.
  Inside `a:ln` the order is fill, `prstDash`, join, `headEnd`, `tailEnd`; a head
  inserted before the fill breaks the schema.
- **Head size follows the line width.** With thin edges (0.75 pt) the default `med`
  head is a speck; use `lg`.
- **Connectors take a shadow from the theme.** Shapes drawn with python-pptx reference
  the theme style (`p:style`), and in the default template that gives every connector a
  soft shadow while custom paths have none. Remove `p:style` and set fill and line
  explicitly.
- **Arcs.** The freeform builder of python-pptx draws straight segments only. The
  preset `arc` shape works but takes its two angles as *visual* angles in 60000ths of a
  degree, clockwise from 3 o'clock (in python-pptx: `adjustments[i] = degrees * 0.6`),
  so end points on an ellipse need trigonometry. A custom geometry with one
  `a:cubicBezTo` has exact end points and accepts a `tailEnd`; `path()` does that.
- **Rounded rectangle.** The default corner radius looks like an agent with soft
  corners. Set `adjustments[0] = 0.5` for a storage.
- **Negative width or height.** python-pptx writes and reloads such a file, PowerPoint
  refuses to open it. `check` reports it.
- **Channel circle.** Draw the line first and the white-filled circle on top. For the
  unidirectional channel the first line must end at the circle's outline, otherwise the
  circle hides the head.
- **Rotation** is clockwise in degrees; the isosceles triangle points up at 0.
- **A straight line as custom geometry** has a bounding box of height or width zero.
  Use a connector for it, which also keeps its end points draggable in PowerPoint.

## Verify: render, enlarge, compare

A diagram is done when a rendering of it has been compared with the reference sheet,
edge by edge: head filled, number of heads, where each head sits, arcs or straight line,
solid or dashed, angular or rounded. Look at enlarged crops, not at the whole slide.
When delegating the check, hand over the rendered image and the reference sheet and ask
for exactly this comparison.

On Windows with PowerPoint, [`scripts/render.ps1`](scripts/render.ps1) writes one PNG
per slide (a running PowerPoint is reused and left open):

```powershell
pwsh scripts\render.ps1 deck.pptx out-png 2880
```

Elsewhere, LibreOffice converts to PDF. Its rendering of arrowheads and custom paths
can differ from PowerPoint's, and this skill's stencil was checked with PowerPoint only:

```sh
soffice --headless --convert-to pdf deck.pptx
```
